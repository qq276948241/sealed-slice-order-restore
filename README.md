# 分段记录日志（纯 Java 标准库）

把记录先写进**打开的一片**内存缓冲对应的片文件，一片写满就**封口**改名；
进程退出后重新打开目录，按每片**封口时间**从早到晚把记录**找回**，
取出的全局顺序与写入时完全一致。

全程只用 `java.base` 里的类（`java.nio.file`、`DataInputStream/OutputStream`、
`CRC32` 等），没有任何第三方包。

## 组成（写入、封口、找回分成互相调用的几截）

- `src/segmentlog/Record.java`：单条记录的帧格式与 CRC32 校验。
  帧 = `长度前缀 + 序号 + 时间戳 + CRC + 负载`，长度前缀让坏帧能被整帧跳过。
- `src/segmentlog/SegmentWriter.java`：当前"打开的一片"，写 `open-NNNNNN.seg`；
  `seal()` 刷盘关闭并原子改名为 `seg-NNNNNN-<封口毫秒>.seg`。
- `src/segmentlog/SegmentReader.java`：顺序读一片；CRC 坏的记录整帧跳过，
  通过异常上报其原始序号，后续好记录序号不变。
- `src/segmentlog/RollingLog.java`：门面。`append` 写满自动封口并开新片、
  分配跨片连续序号；`recover` 按文件名里的封口时间排序（同毫秒用片号兜底）
  逐片读回；重新打开时扫描恢复片号与序号水位。
- `src/segmentlog/FaultInjector.java`：演示工具，翻转某条已封口记录的负载字节。
- `src/segmentlog/Demo.java`：`write` / `read` 两个独立进程阶段。

## 关键语义

- **坏记录跳过不错位**：序号和记录一起落盘，不是读的时候按位置数出来的。
  第 5 条坏了被跳过，第 6 条找回时序号仍然是 6，不补号、不重排。
- **关掉再打开顺序不变**：封口时间写进文件名，`recover` 排序后逐片顺序读；
  片内靠追加顺序、片间靠封口时间，两层顺序都确定。
- **不是单块内存数组**：数据落在多个片文件上，写入、封口、找回分别由
  独立的类承担并互相调用；演示还真的跨进程（write 进程退出后 read 进程重开）。

## 运行

```bash
./run.sh
```

预期：写入 10 条（每片 3 条），注入损坏序号 5；重新打开后找回 9 条好记录，
顺序为序号 1,2,3,4,6,7,8,9,10，跳过列表为 [5]，最后打印 `结果：PASS`。
